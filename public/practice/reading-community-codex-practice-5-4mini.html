- 기존 프로젝트가 있으면 필요한 파일만 수정

기능:

4. 완독 책 목록
5. 책 직접 추가

- GitHub는 아직 하지 않는다.
- Kakao 로그인은 아직 하지 않는다.

/goal
현재 GitHub에 push된 독서 커뮤니티 프로젝트를 Vercel Plugin을 사용해서 Vercel에 연결하고 배포까지 진행해줘.

현재 상태:

1. React + Vite + JavaScript 앱이다.
2. GitHub에 commit & push가 완료되어 있다.
3. 아직 Supabase 연결은 하지 않았다.
4. 먼저 Vercel 무료 배포 주소를 만들고 싶다.
5. 이번 단계에서는 Vercel 웹사이트에서 수강생이 직접 클릭하는 방식이 아니라, Codex에서 Vercel Plugin을 사용해 최대한 자동으로 연결/배포한다.

중요:

* Vercel Plugin을 우선 사용한다.
* Vercel MCP는 이번 단계에서 사용하지 않는다.
* Vercel CLI는 Plugin으로 해결이 안 될 때만 대체 방법으로 제안한다.
* production 배포는 내가 명시적으로 승인하기 전에는 하지 않는다.
* 먼저 preview 배포를 목표로 한다.

먼저 확인할 것:

1. Vercel Plugin이 설치되어 있는지 확인한다.
2. 설치되어 있지 않으면 Codex의 /plugins 메뉴에서 Vercel Plugin을 설치하라고 안내한다.
3. 설치 또는 로그인/권한 승인이 필요하면 어떤 작업이 필요한지 먼저 설명하고 멈춘다.
4. Vercel 계정 인증이 필요하면 브라우저 인증을 내가 직접 진행하도록 안내한다.
5. Vercel Plugin 연결이 확인되면 다음 단계로 진행한다.

Vercel Plugin 사용:

1. 가능하면 /vercel-plugin:status 로 연결 상태와 프로젝트 상태를 확인한다.
2. Vercel 프로젝트가 아직 연결되어 있지 않으면 현재 GitHub repository를 Vercel 프로젝트로 연결한다.
3. Framework Preset은 Vite로 판단한다.
4. Build Command는 package.json 기준으로 확인한다.
5. Output Directory는 Vite 기본값인 dist를 사용한다.
6. npm run build를 먼저 실행해서 배포 가능한지 확인한다.
7. build가 성공하면 Vercel preview 배포를 진행한다.
8. 가능하면 /vercel-plugin:deploy 명령을 사용한다.
9. 배포가 성공하면 .vercel.app 배포 URL을 확인한다.
10. 배포 URL을 README.md, PROJECT_CONTEXT.md, TODO_NEXT.md에 기록한다.

Codex가 할 일:

1. package.json의 scripts 확인
2. Vite 프로젝트 구조 확인
3. npm run build 실행
4. Vercel Plugin 연결 상태 확인
5. Vercel project 연결 또는 연결 방법 안내
6. preview 배포 실행
7. 배포 URL 확인
8. README.md에 Vercel Plugin을 통한 배포 방법 기록
9. PROJECT_CONTEXT.md에 공개 주소 기록 항목 추가
10. TODO_NEXT.md에 Supabase Redirect URL과 Kakao Redirect URL에 이 Vercel 주소를 사용할 것이라고 기록

Vercel에서 필요한 사용자 승인:

1. Vercel 로그인
2. GitHub repository 접근 권한 승인
3. Vercel project 생성 또는 연결 승인
4. 배포 실행 승인

조건:

* 모델 5.4-mini 기준
* Reasoning Medium
* Supabase 연결은 아직 하지 않는다.
* Kakao 로그인은 아직 하지 않는다.
* 환경변수는 아직 추가하지 않는다.
* .env.local은 GitHub에 올리지 않는다.
* service_role key, secret key, database password는 사용하지 않는다.
* 불필요한 리팩터링 금지
* 기존 앱 디자인 변경 금지

배포 정책:

1. 기본은 preview 배포로 진행한다.
2. production 배포가 필요하면 먼저 위험 요소를 요약하고 내 승인을 받아라.
3. production 배포 명령이 필요할 경우 /vercel-plugin:deploy prod 사용 가능 여부를 확인하고 안내한다.
4. 도메인 연결은 이번 단계에서 강제로 하지 말고, 나중에 할 작업으로 문서화한다.

실패 시:

1. Vercel Plugin이 없으면 설치 방법을 안내한다.
2. 인증이 안 되어 있으면 Vercel 로그인 방법을 안내한다.
3. GitHub repo 연결이 안 되면 Vercel에서 GitHub 권한을 확인하라고 안내한다.
4. build가 실패하면 오류를 요약하고 수정한다.
5. 배포가 실패하면 Vercel Plugin으로 로그를 확인하고 원인을 요약한다.
6. 그래도 안 되면 Vercel 웹 UI에서 수동 배포하는 대체 방법을 안내한다.

5. 추가 기능: 강사화면 보기 안정화
────────────────────────────────

기존 HTML 강의자료에 강사화면 보기 기능이 있다면 안정화한다.

목표:
복잡한 스크롤 실시간 동기화, 포인터, 줄긋기 전송은 제거하거나 비활성화하고,
강사가 현재 보고 있는 페이지/섹션으로 수강생 화면을 이동시키는 기능만 유지한다.

요구사항:
1. 강사는 숨은 관리자 단축키를 입력하면 관리자 패널을 열 수 있다.
2. 숨은 관리자 단축키는 화면 어디에도 노출하지 않는다.
3. 일반 수강생 화면에는 관리자 버튼 노출 금지
4. 관리자 패널에는:
   - 강사모드 켜기
   - 강사모드 끄기
   - 현재 페이지 보내기
   - 관리자 패널 닫기
5. 수강생 화면에는:
   - 강사화면 보기
   - 자유보기
6. 수강생은 강사화면 보기 버튼을 눌렀을 때만 이동한다.
7. 동기화 기준은 scrollY가 아니라 pageId / sectionId
8. 포인터/줄긋기 전송은 하지 않는다.
9. 수강생은 절대 broadcast하지 않는다.
10. host 모드이면서 강사모드가 켜져 있을 때만 broadcast한다.
11. sectionId 기반으로 안정적으로 이동한다.
12. followMode가 false이면 강사 이벤트를 무시한다.

완료 조건:
- 혼자 스크롤되는 문제 없음
- 수강생이 버튼을 눌렀을 때만 강사 페이지로 이동
- 숨은 관리자 단축키가 페이지에 노출되지 않음
- 기존 자료 열람 기능 유지
