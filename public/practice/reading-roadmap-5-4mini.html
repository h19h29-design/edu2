Supabase 가입

  • supabase.com 접속 후 가입
  • New project 생성
  • Project name, DB password, Region 입력
  • Data API 또는 API 화면에서 Project URL 확인
  • API Keys에서 Publishable key 확인
  • Authentication에서 Anonymous Sign-in 켜기
Supabase URL은 https://프로젝트ID.supabase.co 까지만 사용합니다. 화면에 보이는 /rest/v1/ 는 빼세요. service_role, secret key, database password는 사용하지 않습니다.

1단계 · MVP 한 번에 만들기

/goal
무료 플랜 Windows Codex 실습용으로 "독서 공유 및 책 읽기 프로그램" MVP를 한 번에 만들어줘.

현재 폴더가 비어 있거나 React/Vite 프로젝트가 아니면, React + Vite + JavaScript 구조로 필요한 파일을 만들어줘.
이미 프로젝트가 있으면 기존 구조를 최대한 유지하면서 최소 수정해줘.

설정 기준:
- 모델은 5.4-mini 기준
- Reasoning은 Medium 기준
- MCP 사용 금지
- 플러그인 사용 금지
- 웹검색 사용 금지
- 새 라이브러리는 꼭 필요할 때만 설치
- 명령어 실행이 필요하면 Codex가 직접 실행하고, 마지막에 npm run build는 1번만 실행

MVP 기능:
1. 모바일에서 보기 좋은 독서 공유 앱 화면
2. 읽는 중 책 목록
3. 완독 책 목록
4. 책 제목, 저자, 진행률 표시
5. 책 추가 기능
6. 책 삭제 기능
7. 읽는 중 / 완독 상태 선택
8. 진행률 입력
9. localStorage 저장
10. 새로고침 후에도 책 목록 유지
11. README.md에 실행 방법과 프로젝트 설명 작성

주의:
- Supabase는 아직 연결하지 말고 TODO로만 남겨줘.
- 도서검색 API도 아직 연결하지 말고 TODO로만 남겨줘.
- .env.local 파일은 아직 만들지 말아줘.
- 초보자용 프로젝트라 구조를 너무 복잡하게 만들지 말아줘.

작업 후 보고:

2단계 · 도서검색 API 붙이기

/goal
현재 독서 공유 앱에 Open Library 도서검색 API 기능을 추가해줘.

조건:
- 무료 플랜 실습이므로 최소 수정
- 모델은 5.4-mini 기준
- MCP 사용 금지
- 플러그인 사용 금지
- 웹검색 사용 금지
- 새 라이브러리 설치 금지
- Supabase는 아직 하지 않음
- 기존 localStorage 저장 기능 유지
- 마지막에 npm run build 1번만 실행

사용할 API:
https://openlibrary.org/search.json?q=검색어&limit=10

기능:
1. 도서검색 입력창과 검색 버튼 추가
2. 책 제목이나 작가명으로 Open Library API 검색
3. 검색 결과 카드에 제목, 저자, 첫 출간연도, ISBN, 표지 표시
4. cover_i가 있으면 https://covers.openlibrary.org/b/id/{cover_i}-M.jpg 사용
5. 결과 카드에 "내 서재에 추가" 버튼 추가
6. "내 서재에 추가"를 누르면 기존 책 목록에 추가
7. 추가한 책은 localStorage에 저장
8. 검색 중, 결과 없음, 오류 상태 표시
9. 가능하면 API 코드는 src/lib/bookSearchApi.js로 분리

작업 후 보고:
1. 변경한 파일 목록
2. 테스트 방법
3. npm run build 결과
4. 다음 단계 TODO

3단계 · Supabase 연결하기

/goal
현재 독서 공유 앱에 Supabase 저장 기능을 연결해줘.

나는 코딩 초보자라서 .env.local 파일도 Codex가 직접 만들어줘.

아래 값으로 프로젝트 루트에 .env.local 파일을 생성하거나 업데이트해줘.

VITE_SUPABASE_URL=여기에_내_SUPABASE_URL_붙여넣기
VITE_SUPABASE_ANON_KEY=여기에_내_Publishable_key_붙여넣기

조건:
- 무료 플랜 실습이므로 최소 수정
- 모델은 5.4-mini 기준
- MCP 사용 금지
- 플러그인 사용 금지
- 웹검색 사용 금지
- @supabase/supabase-js만 필요하면 설치
- service_role, secret key, database password는 절대 사용하지 않음
- 내가 준 키가 service_role 또는 secret처럼 보이면 작업을 멈추고 경고
- .env.local은 GitHub에 올라가지 않게 .gitignore 확인
- .env.example에는 실제 값이 아니라 예시만 작성
- 기존 localStorage 기능은 백업용으로 유지
- 마지막에 npm run build 1번만 실행

기능:
1. src/lib/supabase.js 생성 또는 수정
2. 앱 시작 시 Supabase Anonymous Sign-in 시도
3. Supabase books 테이블에서 내 책 목록 불러오기
4. Open Library 검색 결과를 "내 서재에 추가"하면 Supabase에 저장
5. 직접 추가한 책도 Supabase에 저장
6. 삭제하면 Supabase에서도 삭제
7. Supabase 연결 실패 시 localStorage 방식으로 계속 작동
8. 로딩, 오류, 저장 성공 메시지 표시

데이터 매핑:
- title: 책 제목
- author: 저자명
- status: 기본값 reading
- progress: 기본값 0
- first_publish_year: Open Library의 first_publish_year
- isbn: ISBN 배열이 있으면 첫 번째 값
- cover_url: cover_i가 있으면 https://covers.openlibrary.org/b/id/{cover_i}-M.jpg
- source: Open Library에서 추가한 책은 openlibrary, 직접 추가한 책은 manual

참고:
- Supabase 테이블이 아직 없어서 저장이 실패하면 앱이 멈추지 않게 처리해줘.
- 필요한 설정 안내는 SUPABASE_SETUP.md에 정리해줘.
- 이 단계에서 긴 SQL을 수강생에게 직접 붙여넣으라고 요구하지 말아줘.

작업 후 보고:
1. 변경한 파일 목록
2. Supabase 연결 흐름
3. 브라우저 테스트 방법
4. npm run build 결과
5. 오류가 나면 확인할 항목
6. 내 Supabase 키 값은 그대로 다시 출력하지 말고 가려서 표시

4단계 · GitHub commit & push

/goal
현재 독서 공유 앱 프로젝트를 GitHub에 commit & push까지 진행할 수 있게 처리해줘.

필요한 git 작업은 Codex가 직접 실행하고, 권한 요청이 나오면 내가 승인한다.

GitHub 저장소 주소:
여기에_내_GitHub_repository_URL_붙여넣기

해야 할 일:
1. 현재 프로젝트 상태 확인
2. .gitignore 점검
3. .env.local, .env, node_modules, dist가 커밋되지 않게 확인
4. README.md 보완
5. PROJECT_CONTEXT.md 작성 또는 보완
6. TODO_NEXT.md 작성 또는 보완
7. AGENTS.md 작성 또는 보완
8. git 상태 확인
9. 변경사항 commit
10. main 브랜치로 GitHub에 push
11. remote가 없으면 위 GitHub 저장소 주소로 설정
12. remote가 이미 있으면 위 주소와 맞는지 확인

커밋 메시지:
complete reading app practice

주의:
- Supabase 키나 .env.local 내용은 절대 출력하거나 커밋하지 말 것.
- 실패하면 원인을 쉽게 설명하고, 내가 Codex에 다시 줄 짧은 수정 프롬프트를 제안해줘.
